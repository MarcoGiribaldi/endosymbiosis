A DISCIPLINE FOR HUMAN–AI WORK

No species thrives alone.

Symbiosis is a pact of coexistence between people and AI: laws that protect the user, code when prose is no longer enough, and a system that audits itself — under human veto.

ORIGIN

Born from daily practice, not from a lab.

Every rule in Symbiosis exists because something went wrong first: an agreement the AI forgot, a mistake it repeated, a piece of work it destroyed. Each failure was recorded as data. Each rule that failed twice became code.

THE PROBLEM, MEASURED

A memory you cannot check is worse than no memory.

In a controlled study, an agent with a corrupted memory carried falsehoods into executable output in all three tasks. With the correct memory, or with no memory at all, it made none of those errors. Prose alone is not enough to keep a memory clean.

THE METHOD · THREE STAGES

Each stage begins where the previous one reaches its limit.

FIG. 2 · INTEGRATION.
● PUBLISHED · V2.1

Symbiosis

lineage-based human–AI integration

Laws, still in prose, that protect the user. The memory lives outside the machine and the person stays in charge of it. The machine verifies, names and proposes; the person decides, judges and executes.

Its limit: prose gets contaminated.
Read the manual (v2.1)
● PUBLISHED · V1.1

Endosymbiosis

prose-to-code governance

When prose is no longer enough, rules become code. Each component the system adopts becomes an organ with a declared function and a test that proves it is alive. Oversight shifts from execution to measurement.

Its limit: code grows and must be watched. Already running: ten pieces (the guardian, the canary, the secrets filter…), tested on Linux, Windows and Mac.
Read the page and install the kit
● UNDER CONSTRUCTION · FIRST ORGANS LIVE

Autopoiesis

micro-organisms that sustain the system as it grows

A system that audits and organises itself to preserve the symbiosis. It is judged by deterministic tests, never by another model's opinion; the repairer never repairs itself, and the human veto moves up the stack.

Already running: a daily doctor and self-checking invariants.
A colleague that absorbs your work practice, and a method so every setback builds knowledge.

WHAT WE ARE TESTING

● EARLY RESULTS ARE POSITIVE — several of these mechanisms already run every day and are working as intended. They remain hypotheses until they are measured on more people and more time.

H1 A curated external memory reduces re-explaining and lost decisions, compared with no memory or an accumulated one.
H2 Promoting a rule to code after two violations reduces the recurrence of that class of failure.
H3 Separating author and verifier catches more errors than self-review.
H4 With the method, non-programming experts produce working software in their own domain.
QUESTIONS
Do I need to know how to code?No. The core is a few short text notes; the model reads them and keeps them up to date.
Which models does it work with?With Claude Code, Codex or Antigravity, and also with local models such as Qwen, on your own machine. If you switch models, the method comes with you.
Does my data leave my computer?The core is plain files on your machine, under your control. What you send to the model is your choice.
